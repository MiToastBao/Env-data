# 環評監測資料填報小工具

一個純前端（HTML/CSS/JavaScript）小工具，用來管理多個環評計畫、輸入/匯入各類監測資料，
並匯出成符合「環境監測填寫範本」欄位格式的 Excel 檔。可直接發布在 GitHub Pages 上使用。

## 功能

- **計畫管理**：建立多個計畫（計畫代碼＋計畫名稱），各自獨立管理資料。
- **監測點基本資料**：每個計畫一份，欄位為計畫代碼／書件案號／書件名稱／執行現況／施工日期／
  竣工日期／營運日期／備註，可隨時進入該計畫的頁面補充或修改，匯出時會自動套用。
- **五大監測類別**：空氣品質、水質、地質、噪音、生態，各自的欄位完全對應您提供的範本
  （`空氣品質監測填寫.xlsx`、`水質檢測資料填寫.xlsx`、`地質檢測資料填寫.xlsx`、
  `噪音監測資料填寫.xlsx`、`生態調查資料填寫.xlsx`）。
- **匯入 Excel / PDF**：上傳監測結果檔案後，系統會依欄位名稱自動比對（含常見別名，如「監測地點」
  對應「採樣地點」），並提供一個「對應確認表」讓您在正式匯入前逐欄核對／修正，避免誤植。可一次選取多個檔案。
- **表格編輯**：匯入後的資料以可編輯表格呈現，可直接修改、刪除、或手動新增整列。表格左側固定顯示勾選框、刪除按鈕、「採樣地點」（各類別對應欄位不同：噪音為「監測地點」、生態為「調查地點」）以及「監測項目」欄位（各類別對應欄位不同：水質/空氣品質/地質為「檢測項目」、噪音為「音源發聲特性」、生態為「調查項目」），往右捲動查看其他欄位數值時，仍能同時對照是哪個測站、哪一個測項；表格本身高度固定、內部捲動，橫向捲軸不會被推到頁面最底部。
- **單位代碼／檢測機構代碼**：已內建您提供的《檢測單位代碼表》(161 碼) 與《檢測機構代碼表》
  (AA 及約 104 家機構)，在對應欄位輸入代碼時，會即時顯示代碼所代表的名稱（滑鼠移到欄位上即可看到）。
- **📖 單位代碼表查詢**：頁面右上角可隨時開啟完整的 161 筆單位代碼表，輸入代碼或關鍵字即可搜尋。系統自動比對單位代碼時若不夠確定（例如同一單位符號在代碼表中對應到不只一個代碼），會在匯入預覽畫面顯示提醒並列出受影響的項目，建議您到這裡查證後手動修正。
- **測站座標管理**：座標若是紙本手寫後掃描、不適合自動判讀，可用此工具依「測站＋採樣日期」分組，一次性為每一組輸入座標並套用（同一測站不同次採樣的座標可能略有不同，因此不會被混在一起套用；見下方說明）。
- **座標／日期時間同步確認**：在表格中直接修改某一筆的座標或採樣日期／時間時，若系統偵測到同一份匯入檔案、同一個測站（座標同步還會再比對同一採樣日期）還有其他資料，會跳出確認視窗詢問是否要一併同步，避免誤同步或忘記同步。
- **📦 批次匯入監測報告**：計畫頁面上方可一次選取多個檔案（可跨類別，例如同時選空氣品質、河川水、放流水、營建噪音等原始報告；也支援 PDF，會逐頁嘗試判斷），系統會自動判斷每個檔案／工作表（或頁面）屬於哪個監測類別，逐一帶您確認每個類別的測站設定與監測項目後匯入。目前噪音／水質／空氣品質三類支援自動判斷；地質／生態尚無專屬解析器，請於各分類頁面用一般匯入方式處理。各類別頁面的「匯入資料」也支援一次選取多個檔案（例如同一類別、不同月份的報告）。無論哪種方式，每個來源檔案都會被系統獨立追蹤，即使同時選取多個檔案一起匯入，也不會被誤判成同一份報告（例如同一測站不同月份的資料不會互相同步污染）。
- **監測項目勾選**：匯入資料時，系統會列出報告中偵測到的所有監測項目（不論是智慧解析或一般欄位比對匯入），讓您勾選要匯入哪些項目——不會被固定寫死成某個範本的項目數量，每個計畫案報告裡有哪些項目就會列出哪些，可依實際需求增減。
- **時間欄位直接輸入**：時間欄位改為文字輸入（不再是容易滑動選不到的原生時間滾輪選單），可直接打「1430」「14:30」皆可，離開欄位時會自動整理成 HH:MM 格式顯示（不顯示秒數，符合官方範本本身的格式）；日期欄位同樣改為文字輸入，顯示「西元/月/日」格式（如 2026/05/12），可直接打「2026/5/12」或「2026-5-12」。內部儲存與匯出仍維持與範本相容的格式，不受顯示格式影響。
- **同批次同測站的日期/時間/座標/檢測類別同步（都會先詢問）**：從同一份檔案匯入的資料，如果事後在表格中修正某一筆的採樣日期、時間、座標或檢測類別，系統會跳出確認視窗，詢問是否要把「同一份檔案、同一個地點」（座標與檢測類別還會再比對「同一採樣日期」，避免同一測站不同次採樣的資料互相污染）的其他資料列一併同步更新——選「確定」才會套用，選「取消」則只修改這一筆。
- **🧪 檢測方法管理與跨季記憶**：依測項（如 SO2、總磷、Leq）列出目前資料中出現過的所有項目，可統一補上或修改檢測方法／單位代碼，套用到所有相同測項的資料列。系統會記住您確認過的設定（存在該計畫底下），下一次（含下一季）匯入同一計畫的資料時，若報告本身沒有提供某測項的檢測方法，會自動帶入先前記住的值；仍然缺少的話，匯入預覽畫面會列出提醒。
- **匯入重複資料偵測**：匯入時若發現日期／時間／地點／測項都跟目前已有的資料完全相同，會跳出提醒，可選擇排除重複資料、只匯入不重複的部分。
- **落塵量報告支援**：空氣品質智慧解析新增支援「落塵量」報告格式（一個測項對應多個測站的直式表格），會自動辨識並匯入。
- **匯出**：可依單一類別匯出（檔名與範本一致，例如 `E-2173_空氣品質監測填寫.xlsx`），
  也可一次匯出計畫底下所有已填寫的類別。匯出的 Excel 結構（工作表名稱、欄位順序）與您提供的
  空白範本完全一致。
- **備份／還原**：因為是純前端網站、資料存在瀏覽器裡（見下方「資料儲存方式」），
  頁面右上角提供「匯出備份」／「匯入備份」，可將所有計畫資料打包成一個 JSON 檔，
  用於換電腦、換瀏覽器，或作為資料保險。

## 版本紀錄

頁面標題右邊有一個版本徽章（例如 `v1.4`），點擊可開啟完整更新紀錄。**更新後畫面若沒有變化，請先確認這個版本號是否已經變成最新版**，若還是舊版號，代表 GitHub Pages 可能還沒部署完成（通常 1-2 分鐘），或瀏覽器快取了舊版本，可嘗試強制重新整理（Windows/Linux：Ctrl+Shift+R；Mac：Cmd+Shift+R）。

## 資料管理（新增／刪除／批次操作）

- **計畫刪除**：進入計畫頁面後，右上角「刪除計畫」可刪除；左側計畫清單每個項目也直接有 🗑 圖示，不需要先點進去才能刪除。
- **匯入紀錄管理**：每個類別頁面上方「📜 匯入紀錄」可查看這個類別過去每一次匯入的紀錄（時間、來源檔案名稱、匯入方式、筆數），可針對單一次匯入整批刪除，不需要在表格裡一筆一筆找。（手動新增／編輯的資料不會出現在匯入紀錄裡，請用下面的批次勾選刪除。）
- **表格內多選批次刪除**：資料表格每列前方新增勾選框，表頭也有「全選」；勾選後上方會出現「刪除已選取」工具列，可一次刪除多筆，不論是匯入的還是手動輸入的資料都適用。
- **清空此類別**：類別頁面上方「🗑 清空此類別」可一次清空該類別全部資料（含匯入紀錄），用於整批重做。
- **匯出可勾選類別**：「匯出全部類別」會先跳出勾選畫面，只列出目前有資料的類別，可自行決定要匯出哪些，不一定要全部匯出。若這些類別裡有多個期別的資料，還會出現「只匯出哪一期」的選單，預設不會混雜期別，除非您主動選擇「全部期別」才會一次匯出所有季度的資料。
- **年/季期別標記與篩選**：匯入資料時，系統會依採樣日期自動猜測所屬「年/季」（如「115年第2季」），可手動確認或修改。各類別頁面上方會出現「期別」下拉選單，可切換只查看/編輯某一期的資料；「匯出此類別」也會依此篩選範圍匯出，確保匯出的檔案不會混雜其他季度的資料。
- **表格內容搜尋篩選**：各類別頁面上方新增「🔍 搜尋任何欄位內容」輸入框，打關鍵字（測站名稱、測項、日期等）即可即時篩選畫面上顯示的資料列，方便快速檢查或修正特定資料；純粹是畫面篩選，不影響匯出範圍（匯出範圍由期別篩選決定）。搜尋篩選狀態下，「全選」與批次刪除都只會作用在目前看得到的資料，不會誤動到被篩選隱藏的其他資料。
- 以上刪除操作都會有二次確認視窗，避免手滑誤刪。

## 重要說明：資料儲存方式與限制

這個工具設計成**純靜態網站**，可以直接放上 GitHub Pages 免費發布，因此**沒有伺服器、沒有資料庫**。
所有輸入的資料都儲存在**目前瀏覽器的 localStorage** 中，這代表：

- 資料只存在「這一台電腦、這一個瀏覽器」裡，換瀏覽器或換電腦不會自動同步。
- 清除瀏覽器快取／網站資料，或使用無痕模式，資料會遺失。
- **強烈建議**：資料量大或重要時，定期使用右上角「匯出備份」下載 JSON 備份檔另外保存；
  需要在別台電腦繼續作業時，用「匯入備份」還原。

如果您之後希望做到「多人共用、雲端同步」，會需要加上一個真正的後端（例如 Firebase、
Supabase 或自架 API），這已超出純 GitHub Pages 靜態網站的能力範圍，需要另外規劃。

## 關於「自動抓取資料」的實際做法

您的原始檢測報告（華光工程顧問股份有限公司格式）並不是乾淨的表格，而是像紙本報告一樣、欄位標籤和數值散落各處的「表單」格式。針對這種真實情況，本工具內建了**表單智慧解析**功能：

- **噪音類別**：可直接辨識「固定音源噪音測定報告（營建工程）」「低頻噪音測定報告」「環境噪音/ 振動 24 小時報告」三種報告格式，自動抓取日期、時間、座標、Leq/Lmax／Lvd(10) 數值、法規依據、檢測方法、檢測機構等欄位。
- **水質類別**：可辨識檢驗項目直式表格格式的報告，逐項抓取檢測值、偵測極限、單位、方法。
- **空氣品質類別**：可辨識 24 小時連續監測報告，自動抓取報告中實際出現的所有污染物項目（SO2、NO2、NOx、NO、CO、O3、CH4、NMHC、THC、PM10，以及側表的 TSP、PM2.5，不侷限固定 7 項）的日平均值、對應單位代碼、各項目的檢測方法（讀取報告備註欄的方法對照表取得，比寫死更準確也更不容易過時）、檢測機構。系統抓到哪些項目就會全部列出，匯入時再由您勾選實際要送件的項目（見下方「監測項目勾選」說明）。（此報告格式本身不含 GPS 座標，需透過下方「測站座標管理」補充一次。）系統會直接讀取 Excel 檔案本身的「欄位隱藏」設定，判斷這個測站是否實際有監測某個污染物——因為許多檢驗室共用同一套報告範本，測站沒有裝設對應儀器的項目欄位會被設定隱藏（但儲存格裡仍留有無意義的佔位文字），系統偵測到隱藏欄位會自動略過該項目並跳出提醒，不會誤當成真實測值匯入；若欄位是可見的，則正常判讀（含合理的「低於偵測極限」讀值）。
- 上傳一個檔案（可能內含多個工作表，例如一次上傳一整份報告，內含 20～30 個測站）時，系統會**自動掃過每個工作表**，能辨識的就抓取，不能辨識的會列出來讓您知道被略過了。

**準確度**：以上三種格式都已經用您提供的實際季報告，逐欄位比對「已完成填寫版本」核對過——日期、時間、數值、單位代碼、檢測方法、檢測機構代碼皆與正式送件版本完全一致。唯一無法從報告本身取得、需要靠「測站設定」補充的，是 GPS 座標、正式站名、管制區等這類報告中本來就沒有記載的資訊。

**測站設定（重要）**：報告本身不會包含所有欄位（例如噪音報告的「監測地點」欄位常是概略描述如「Y1車站~Y4車站」，但正式送件用的是特定站名如「YC01標工區周界外」；水質與空氣品質報告則完全不含GPS座標）。因此匯入時會先顯示一個「測站設定」畫面，讓您依報告內的**測點編號**逐一補上正式站名／座標／管制區等資訊，勾選「記住此設定」後，之後同一測站的資料再匯入就會自動套用，不用每次重填。

**座標為手寫掃描件時**：如果您的原始報告座標是紙本手寫後掃描的（無法可靠自動判讀），建議略過匯入時的座標欄位、直接匯入其他資料，事後在每個類別頁面上方點選「📍 測站座標管理」，畫面會依「測站＋採樣日期」列出每一組（同一測站若在不同日期採樣過，會分開列出，因為座標可能略有不同），為每一組輸入座標後按「儲存並套用」，只會套用到該測站、該採樣日期的資料列——不會影響到同一測站其他次採樣的資料。此工具在五個監測類別（空氣品質／水質／地質／噪音／生態）都可以使用，且會直接讀取／寫入目前表格中的資料，跟資料來源（匯入或手動新增）無關。全部類別的座標都補齊後，即可用「匯出全部類別」一次性匯出完整檔案。

**ND／比較關係的填寫規則**：水質類別的智慧解析已對照官方填寫範本說明與您實際送件的資料驗證過，規則如下——測值為 ND 時，「比較關係」與「檢測數值」兩欄都填 `ND`；測值為「< A」時，「比較關係」填 `<`、「檢測數值」填 A 本身的數字；不論何種情況，只要原始報告有列出偵測極限，「檢測極限」欄一律照實填入，三者互相獨立、不會因為是 ND 就漏填極限。另外，若測項本身沒有單位（例如 pH 值），「檢測濃度/質量單位」會正確填入代碼 161（無），不會留空白。

**PDF 匯入的判讀能力**：噪音／水質／空氣品質的智慧解析現在也會嘗試套用在 PDF 上（無論是各分類頁面的「匯入資料」或計畫頁面的「批次匯入」），做法是把 PDF 逐頁的文字依座標重新組成類似 Excel 儲存格的表格，再用跟 Excel 一樣的判讀邏輯去找欄位。但 PDF 終究是圖像化的版面、不是結構化資料，準確度天生低於 Excel（例如掃描歪斜、字型特殊、版面複雜時容易誤判），系統偵測到資料來自 PDF 時會在匯入預覽畫面跳出提醒，請務必逐筆核對後再匯入，尤其是數值與座標欄位。若您手上有原始 Excel 檔，仍強烈建議優先使用 Excel 匯入。

**地質／生態類別**：目前尚未提供對應的原始報告範例，所以還是使用一般的 Excel 欄位比對匯入（會嘗試自動比對欄位名稱，比對錯誤可在匯入前逐欄修正）。

一般 Excel 欄位比對匯入的運作方式：

1. **自動比對**：以欄位名稱做比對（完全相同 → 常見別名 → 部分包含），盡量猜出對應關係。
2. **人工確認**：匯入前一定會出現「對應確認表」，列出目標欄位（如「檢測數值」）目前對應到您
   檔案中的哪一欄，您可以用下拉選單修正錯誤的對應、或設定「不匯入」。
3. 確認後才會把資料寫入表格，且**都還可以在表格中手動再次修改**。

PDF 匯入是「輔助功能」：程式會嘗試從 PDF 文字座標重建表格列，但掃描版 PDF、複雜排版
的表格準確度會明顯較低，**強烈建議優先使用 Excel/CSV 格式匯入**，PDF 僅作為備用。

## 如何發布到 GitHub Pages

1. 在 GitHub 建立一個新的 repository（例如 `env-monitoring-tool`）。
2. 把這個資料夾（`index.html`、`css/`、`js/`）裡的所有檔案上傳到 repository 的根目錄
   （或 `docs/` 資料夾，兩種都可以，只要等一下設定對應）。
3. 到 repository 的 **Settings → Pages**：
   - Source 選擁「Deploy from a branch」
   - Branch 選 `main`（或您的預設分支），資料夾選 `/ (root)`（或您放檔案的 `docs/`）
   - 儲存後，GitHub 會給您一個網址，例如 `https://你的帳號.github.io/env-monitoring-tool/`
4. 等 1-2 分鐘部署完成後，開啟該網址即可使用。

> 小提醒：本工具用到的兩個外部函式庫（Excel 讀寫用的 SheetJS、PDF 讀取用的 pdf.js）是透過
> `index.html` 裡的 CDN 連結載入，開啟網頁時需要能連上網路（`cdnjs.cloudflare.com`）。
